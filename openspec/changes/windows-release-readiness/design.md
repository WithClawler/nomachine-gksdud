# Design

## Context

전달본의 RememberKey는 이미 즉시 저장한다. 앱의 #SingleInstance Force는 스크립트 경로별로 동작하므로 다른 폴더의 사본까지 보호하지 않는다. 자동 시작은 현재 실행 파일을 가리키는 사용자 링크이며 설치기는 이를 갱신하지 않는다. 동기는 proposal.md를 따른다.

## Goals / Non-Goals

**Goals:** 검증된 키 전송 경로를 유지하고 설치 수명주기와 실제 Windows CI 증거를 보강한다.

**Non-Goals:** Mac 입력기를 직접 제어하거나 NoMachine 공식 판별 API를 구현하지 않는다. CI의 모의 연결 검사를 물리 키나 실제 원격 OS 검사로 대체하지 않는다.

## Decisions

- 경로에 무관한 Local named mutex를 매핑 초기화 전에 획득한다. 경로별 강제 종료 대신 중복 사본만 종료하며 설치기도 동일 mutex로 실행 중 업그레이드·제거를 차단한다. 다른 사용자 세션은 독립적이다.
- 자동 시작 링크는 명시적 설정 저장 때 생성한다. 설치 후 유지보수 모드는 기존 앱 전용 링크만 새 경로로 갱신하고 일반 실행·신규 설치 때 자동 선택하지 않는다. 제거도 자신을 가리키는 링크만 삭제한다.
- 실제 키의 VK+SC 저장과 검증된 VK 핫키 바인딩을 유지한다. 테스트 주입점으로 detector·출력 sink·임시 설정 경로를 사용하되 일반 실행에는 별도 QA transport나 원격 제어 기능을 넣지 않는다.
- Windows Actions에서 원본 회귀 검사부터 실행한다. 변경본에서는 프로세스 재시작/폴더 이동, 중복 사본, 예약 전송, 실제 EXE 설치·업데이트·제거를 검사한다. 비관리자 계정은 격리된 CI runner 안에만 생성하고 종료 후 정리한다.
- 배포 파일은 명시적 manifest로 허용하고 다운로드 해시·패키지 목록·런타임 원본 소스 동봉을 검사한다. 공개 릴리스는 alpha 상태와 검증 한계를 표시한다.

## Risks / Trade-offs

- NoMachine 로그 형식·Windows IME·키보드의 차이 → 기존 검증 경로를 유지하고 증거가 불충분하면 매핑하지 않는다. 여러 버전과 실제 연결은 별도 실기 검증 대상으로 남긴다.
- 실행 중인 기존 0.1.2 사본은 새 mutex를 모른다 → 첫 업그레이드 때 기존 사본을 트레이에서 종료하도록 안내한다. 새 버전 사본 간에는 mutex를 적용한다.
- 설치 중 앱 실행 → installer mutex로 안전하게 실패하거나 종료 안내를 표시하며 다른 AHK 프로세스를 종료하지 않는다.
- 서명 없는 초기 EXE → alpha로 명시하고 해시를 제공한다. 코드 서명은 자격 증명 없이 구성하지 않는다.

## Migration Plan

사용자 settings.ini 스키마와 위치를 유지한다. 기존 portable의 자동 시작 링크가 있으면 설치 후 해당 설치로 갱신한다. 문제 발생 시 앱 종료 후 이전 버전으로 되돌릴 수 있고 설정은 유지된다.
